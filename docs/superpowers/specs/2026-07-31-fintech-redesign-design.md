# Финтех-редизайн фронтенда на React Aria Components

**Дата:** 2026-07-31
**Статус:** утверждён к реализации
**Проект:** Scrudge Finance Bot — Telegram Mini App учёта семейных расходов

---

## 1. Контекст и цель

Приложение работает: бэкенд на aiohttp/aiogram, данные в Google Sheets, хостинг Render.
Фронтенд — один файл `webapp/index.html` (1358 строк, vanilla HTML/CSS/JS, без сборки).

Проблемы текущего фронтенда:

- Визуальная незрелость: эмодзи вместо иконок, слабый контраст подписей, градиент размазан по всему интерфейсу.
- Хрупкость: видимость экрана зависела от срабатывания CSS-анимации — привело к белому экрану в Telegram (исправлено в `676910e`, но архитектурная хрупкость осталась).
- Интерфейс ждёт ответа Google Sheets (~1 с) на каждую запись.
- Ручные компоненты (дата-пикер, селекты) без доступности и без состояний фокуса.

**Цель:** переписать фронтенд на React + React Aria Components (Tailwind-версии с
react-aria.adobe.com), переработать layout по канонам финтех-продуктов, поднять контраст,
заменить эмодзи на профессиональный иконочный набор. Цветовую гамму сохранить.

## 2. Границы работы

**В объёме:**

- Новый фронтенд в каталоге `frontend/`, собираемый Vite.
- Два новых маршрута в `bot/main.py` для раздачи собранного фронта.
- Многостадийная сборка в `Dockerfile`.
- Команда бота `/beta` для тестирования нового UI.

**Вне объёма (не трогаем):**

- HTTP API: `/api/auth`, `/api/expense`, `/api/stats`, `/api/rates`, `/api/meta` — контракты
  остаются побайтово теми же.
- Схема Google Sheets: листы `RAW` и `META`, порядок колонок, форматы дат.
- Логика бота: `/start`, `/add`, `/stats`, `/export`.
- Keep-alive, деплой на Render, переменные окружения.
- Старый `webapp/index.html` — остаётся рабочим и раздаётся с `/` до момента переключения.

## 3. Архитектура

### 3.1 Структура каталогов

```
frontend/
  index.html
  package.json
  vite.config.ts
  src/
    styles.css               Tailwind v4: @import и @theme с токенами палитры
    main.tsx                 точка входа, ErrorBoundary, провайдеры
    app.tsx                  оболочка, табы, роутинг состоянием
    screens/
      Overview.tsx           главный экран
      Operations.tsx         календарь и список операций
      Analytics.tsx          графики (ленивый чанк)
    sheets/
      AddExpenseSheet.tsx    шторка создания и редактирования траты
    components/
      KpiHero.tsx            сумма месяца и дельта
      PayerSplit.tsx         распределение Vova / Karina
      CategoryTile.tsx       плитка категории
      TxRow.tsx              строка операции
      MoneyText.tsx          числа с tabular-nums
      Skeleton.tsx           состояния загрузки
      EmptyState.tsx         пустые состояния
    lib/
      api.ts                 обёртки над эндпоинтами
      money.ts               форматирование и конвертация валют
      icons.ts               соответствие категория и источник → иконка
      useExpenses.ts         загрузка, кэш, оптимистичные мутации
      theme.ts               тема из Telegram, светлая и тёмная
```

### 3.2 Сборка

Зависимости: `react`, `react-dom`, `react-aria-components`, `@phosphor-icons/react`,
`recharts` (графики), `tailwindcss` v4 с `@tailwindcss/vite`, плагин
`tailwindcss-react-aria-components` для стилизации состояний RAC.

Tailwind v4 настраивается из CSS, файла `tailwind.config.ts` нет: токены палитры
объявляются в `src/styles.css` через `@theme`.

Vite собирает в `frontend/dist`. Ключевые настройки:

- `base: '/v2/'` — иначе пути к ассетам сломаются на подпути.
- `build.target: ['es2020', 'safari14']` — Telegram Desktop у пользователя рапортует
  WebApp API 6.0, то есть старый WebKit. Свежий синтаксис недопустим.
- Ручное разделение чанков: экран `Analytics` вместе с `recharts` выносится в отдельный
  чанк и грузится по требованию.

`Dockerfile` становится многостадийным:

```dockerfile
FROM node:20-slim AS ui
WORKDIR /ui
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ ./
RUN npm run build

FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
COPY --from=ui /ui/dist ./webapp/v2
CMD ["python", "bot/main.py"]
```

### 3.3 Маршруты бэкенда

В `bot/main.py` добавляются два маршрута. **Регистрировать строго до** существующего
catch-all `app.router.add_get("/{filename}", serve_static)` — иначе он перехватит `/v2`.

| Маршрут | Отдаёт |
|---|---|
| `GET /v2` | `webapp/v2/index.html` |
| `GET /v2/{path:.*}` | статика из `webapp/v2/` |

Команда `/beta` в боте отправляет кнопку WebApp на `with_cache_bust(WEBAPP_URL + "/v2")`.

## 4. Экраны и layout

Нижняя навигация: три вкладки и центральная кнопка добавления.

```
[ Обзор ]   [ Операции ]   ( + )   [ Аналитика ]
```

### 4.1 Обзор — главный экран

Сверху вниз:

1. **Герой месяца.** Сумма за текущий месяц крупно, `tabular-nums`, вес 500. Рядом дельта
   к прошлому месяцу со знаком и цветом (`--pos` при снижении трат, `--neg` при росте).
   Переключатель валюты UAH / USD / PLN.
2. **Распределение плательщиков.** Горизонтальный бар Vova / Karina с суммами и долями.
3. **Топ-5 категорий.** Иконка, название, сумма, `Meter` с долей от месячного итога.
4. **Последние 5 операций.** Тап открывает шторку редактирования.

### 4.2 Операции

- Календарь-хитмап: насыщенность фона дня пропорциональна тратам.
- `DateRangePicker` для произвольного периода.
- `SearchField` — поиск по описанию и категории.
- Список операций выбранного периода, группировка по дням, тап — редактирование.

### 4.3 Аналитика

- Донат по категориям взамен текущего canvas-пирога.
- Столбцы по дням или неделям в зависимости от длины периода.
- Сравнение с предыдущим периодом.
- Разбивка по источникам денег.

### 4.4 Шторка добавления

Открывается центральной кнопкой, работает и на создание, и на редактирование:
сумма, валюта, категория сеткой, источник чипами, дата, описание, кто платил.
Первичное действие — «Записать», при редактировании доступно удаление.

## 5. Компоненты React Aria Components

Берутся Tailwind-версии с react-aria.adobe.com.

| Назначение | Компонент |
|---|---|
| Шторка снизу | `Modal` + `Dialog` |
| Ввод суммы | `NumberField` |
| Валюта, плательщик | `ToggleButtonGroup` |
| Сетка категорий, чипы источников | `GridList` |
| Дата траты | `DatePicker` + `Calendar` |
| Период в аналитике и операциях | `DateRangePicker` |
| Описание | `TextField` |
| Навигация между экранами | `Tabs` |
| Доля категории | `Meter` |
| Переименование и удаление своей категории | `MenuTrigger` + `Menu` + `Popover` |
| Поиск операций | `SearchField` |
| Подтверждение записи | `Toast` |
| Все кнопки | `Button` |

Намеренно не используются: `Table`, `Slider`, `Tree`, `ComboBox` — на узком мобильном
экране не дают ценности.

Если в установленной версии `react-aria-components` компонент `Toast` отсутствует,
реализуется минимальный собственный на области `aria-live="polite"` — без сторонних
библиотек уведомлений.

## 6. Дизайн-система

### 6.1 Цвета

Базовая гамма сохраняется без изменений:

```
--grad: linear-gradient(135deg, #AA00FF 0%, #FF9500 40%, #FFE620 70%, #68CE66 100%)
--ac:   #FF9500

тёмная:  --bg #08080a  --s1 #111114  --s2 #19191f
светлая: --bg #f5f5f7  --s1 #ffffff  --s2 #ededf0
```

Изменения:

- **Градиент применяется только к двум сущностям:** сумма-герой и первичная кнопка.
  В текущем интерфейсе он повсюду, из-за чего теряет силу.
- **Добавляются два семантических цвета:** `--pos #68CE66` (уже в палитре) и `--neg #FF5A5F`
  (новый, гармонирует с оранжевым акцентом).
- **Контраст доводится до WCAG AA:** основной текст ≥ 7:1 к фону, вторичный ≥ 4.5:1.
  Подписи плиток категорий переводятся с третичного серого на основной цвет с весом 500 —
  сейчас они светло-серые на светло-сером и практически нечитаемы.

### 6.2 Типографика

- Poppins для интерфейса, JetBrains Mono для чисел — как сейчас.
- Все числовые значения: `font-variant-numeric: tabular-nums`.
- Веса 300–600. Вес 700 и выше на финансовых данных не используется.
- Трекинг: `-0.02em` для крупных чисел, `0.15em` для мелких прописных подписей.

### 6.3 Движение

- Кривые: вход `cubic-bezier(0.16, 1, 0.3, 1)`, выход `cubic-bezier(0.55, 0, 1, 0.45)`.
- Длительности: 150 мс микрообратная связь, 200 мс ховер, 300 мс переходы, 500 мс крупные раскрытия.
- Ховер-подложки 3–4 % прозрачности, бордеры через прозрачность, не сплошным цветом.

### 6.4 Инвариант видимости

**Видимость любого элемента не должна зависеть от того, отработала ли анимация.**

Базовое состояние элемента — видимое; анимация только добавляет входное движение и всегда
имеет явный кадр `from`. Причина правила: 2026-07-30 форма расхода была полностью прозрачной
(`opacity: 0` при `display: block` и корректной высоте), потому что единицу прозрачности
выставляла исключительно анимация `viewIn`. Исправлено в `676910e`.

## 7. Слой данных

`useExpenses.ts` инкапсулирует работу с API:

- Загрузка операций за три месяца при старте, как сейчас.
- Кэш в памяти, инвалидация после мутаций.
- **Оптимистичные мутации.** Создание, изменение и удаление немедленно применяются к
  локальному состоянию; запрос к бэкенду идёт следом. При ошибке состояние откатывается и
  показывается `Toast` с возможностью повторить. Сейчас интерфейс ждёт ответа Google Sheets
  около секунды на каждое действие.
- Роль пользователя по-прежнему в `localStorage` под ключом `role`.

Внешние библиотеки управления состоянием не вводятся: объём данных мал, хватает `useState`
и `useReducer`.

## 8. Обработка ошибок и состояния

- `ErrorBoundary` в корне: при исключении показывает читаемое сообщение с текстом ошибки и
  кнопкой перезагрузки. Белый экран как исход недопустим.
- Загрузка — скелетоны, повторяющие форму контента. Спиннеры не используются.
- Пустые состояния оформлены: иконка, короткий текст, действие. Не «Нет данных».
- Сетевые ошибки — `Toast` с кнопкой повтора, приложение остаётся работоспособным.

## 9. План выката

1. Новый фронт собирается и раздаётся с `/v2`. Старый UI на `/` не затрагивается.
2. Команда бота `/beta` открывает `/v2` — проверка в реальном Telegram на устройстве
   пользователя.
3. После подтверждения: `/` начинает отдавать новый фронт.
4. Старый `webapp/index.html` сохраняется ещё один релиз как аварийный откат, затем удаляется.

## 10. Риски и меры

| Риск | Мера |
|---|---|
| Старый WebKit в Telegram Desktop не понимает свежий синтаксис | `build.target: ['es2020','safari14']`, проверка на реальном клиенте до переключения `/` |
| Вес бандла (React + RAC ≈ 180 КБ gz) замедляет холодный старт | Экран аналитики и графики — ленивый чанк; keep-alive уже не даёт сервису засыпать |
| Сборка Node увеличивает время деплоя на бесплатном Render | Кэш слоёв `npm ci`; рост около 1–2 минут, в лимиты укладывается |
| Регрессия при переписывании логики | API и схема Sheets не меняются; выкат через `/v2` с рабочим откатом |
| Расхождение форматов данных | `money.ts` покрывается тестами на форматирование и конвертацию валют |

## 11. Критерии приёмки

1. `/v2` открывается в Telegram и показывает заполненный интерфейс — не белый экран.
2. Создание, изменение и удаление траты корректно отражаются в листе `RAW`.
3. Пользовательские категории и источники читаются и пишутся через `/api/meta`.
4. Переключение валют пересчитывает суммы по курсам из `/api/rates`.
5. Светлая и тёмная темы соответствуют WCAG AA по контрасту текста.
6. Ни один экран не теряет видимость при отключённых CSS-анимациях.
7. Запись траты ощущается мгновенной за счёт оптимистичного обновления.
8. Старый интерфейс на `/` продолжает работать до момента переключения.
